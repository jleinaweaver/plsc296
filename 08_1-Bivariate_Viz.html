SLIDE: Let’s start our bivariate analyses with two ordinal variables

Categorical x Categorical

ggplot(diamonds, aes(x = cut)) +
  geom_bar()

We’ll begin our bivariate analysis with a univariate step

  • Our interest is in seeing if the types of diamond cuts explain variations in diamond prices

  • For this we want to begin by putting the predictor, or independent variable, on the x-axis


I will now step you through THREE different types of bar plot for visualizing this relationship

  • SLIDE: The first type of bivariate bar plot is what we call a side-by-side plot

Categorical x Categorical

# Side-by-side bar plots
ggplot(diamonds, aes(x = cut, fill = price2)) +
  geom_bar(position = "dodge")

To get to the side-by-side bar plot we add two things to the code

  • We “fill” in the outcome variable which defines the legend, and

  • We add a position argument to tell ggplot what kind of bar plot to make


In terms of representing a relationship remember:

  • The independent variables goes on the x axis

  • The dependent variable is the legend

  • This way we compare the price distribution across each level of the independent variable


Let’s now clean this visualization up

  • SLIDE: First needed fix: the order of values in the legend

Categorical x Categorical

# Side-by-side bar plots
ggplot(diamonds, aes(x = cut, fill = price2)) +
  geom_bar(position = "dodge") +
  scale_fill_discrete(limits = c("100th", "75th", "50th", "25th"))

Call me crazy, but number in a plot should go in descending order

  • Our brains are not wired to think higher is lower


Moving forward I am using code highlighting to draw you to the only thing that changed from the last run of the code

  • SO, the code is identical to the last plot you made but now we’ve added one more function

  • You will need to add the “+” on line 3 to let ggplot know there is a new function to add

SLIDE: Given the uneven bars, let’s consider one final approach to making a bivariate bar plot

Categorical x Categorical

# Proportionate bar plot
ggplot(diamonds, aes(x = cut, fill = price2)) +
  geom_bar(position = "fill") +
  scale_fill_discrete(limits = c("100th", "75th", "50th", "25th")) +
  labs(x = "Diamond Cuts", y = "Count", fill = "Prices") +
  scale_y_continuous(labels = scales::percent)

Last style of common bar plot is a proportional stacked bar plot.

  • This only requires a change to the position argument, BUT

  • You will definitely want to change the axis labels to %s so let’s say it takes two changes to the code


Proportional stacked bar plots are a very cool approach

  • They transform each stacked bar to a proportion of 100% per x variable level.

  • So, the y-axis marks off the proportion of the total represented by each level of the fill variable.


SLIDE: Annoyingly, we need one more piece of code to fix the order within each bar

Categorical x Categorical

# Reverse the order of the levels
diamonds$price3 <- fct_rev(diamonds$price2)

ggplot(diamonds, aes(x = cut, fill = price3)) +
  geom_bar(position = "fill") +
  scale_fill_discrete(limits = c("100th", "75th", "50th", "25th")) +
  labs(x = "Diamond Cuts", y = "Count", fill = "Prices") +
  scale_y_continuous(labels = scales::percent)

R already sees our ordinal price variable as having levels, but the bar plot needs us to reverse them

  • Hence, we create a NEW version of the price variable but with the levels backwards

  • Did everybody get this?


I want to be clear, stacked bar plots are useful and VERY frequently used

  • BUT they are VERY dangerous


In our data, there are over 21k ideal cut diamonds and 1k fair cut diamonds

  • Small changes in the value of fair cut diamonds will have a HUGE impact on the %s

  • e.g. In a room of 10 people, losing 2 is a 20% decrease

  • WHEREAS small changes in the values of ideal cut diamonds will have basically no effect on the %s

  • Does this danger make sense?


Bottom line, be VERY careful with comparing proportions across groups

  • If the group sizes are equal, go nuts

  • If not, beware

  • THIS is why we use quartiles so often, they create equal sized groups for comparisons!

Next visualization challenge!

  • We have an outcome variable that is interval (diamond prices), and

Last class we calculated summary statistics of the interval variable for each level of the categorical variable using the aggregate function

  • Today I’ll show you TWO options for visualizing this relationship


SLIDE: Our first option is simply to make separate histograms for each type of diamond cut

# Interval x Categorical Option 1. Facet Wrap
ggplot(diamonds, aes(x = price)) +
  geom_histogram(bins = 20, color = "white") +
  facet_wrap(~ cut)

Ok, your first option is to use the facet_wrap function to extend ANY univariate visualization into the levels of the categorical variable

  • Use a tilde and then the categorical variable

  • Did everybody get this code to run?


SLIDE: When using a facet wrap you should choose a layout that makes comparisons easier for the viewer

# Interval x Categorical Option 1. Facet Wrap
ggplot(diamonds, aes(x = price)) +
  geom_histogram(bins = 20, color = "white") +
  facet_wrap(~ cut, ncol = 1)

It is simply easier to compare distributions of this shape when they are stacked on top of each other

  • Other types of plot will lead you to different layouts


SLIDE: One more important tweak when using facet wraps

# Interval x Categorical Option 1. Facet Wrap
ggplot(diamonds, aes(x = price)) +
  geom_histogram(bins = 20, color = "white") +
  facet_wrap(~ cut, ncol = 1, scale = "free_y")

Facet wrap forces all of the plots to be on the same x and y axis range

  • Clearly, this makes the “fair” distribution impossible to view


scale = “free_y” tells the facet wrap to let the y-axis ranges vary in each level of the categorical variable

  • This way we can view the distribution of “Fair” on its own terms

  • This helps us compare the distributions across the levels

Box plots are an excellent way to compare IQRs across the levels of a categorical variable

  • Or medians which tell us nothing about the spread of the data

  • The boxes give us a wide version of the “middle” we can compare!
